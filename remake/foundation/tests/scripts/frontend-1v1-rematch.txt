# P0 taps for the release-gate 1v1 run: TWO HUMANS, three rounds (issue #23).
#   --screen=title --local-players=2
#
# WHY a script: a headless run's only real device is the keyboard, which is controller 0
# (`--local-players` drives the pad-less controllers with its synthetic menu/battle patterns
# and never overrides a device). Synthetic input is NOT physical-controller evidence.
#
# Round 1 is the measured cycle of tests/scripts/frontend-4p.txt, replayed for this
# participant count: the title scene is created at tick 0, the selection scene at tick 34,
# the stage page opens when the synthetic pad's OK confirm is accepted (selection-frame 169,
# tick 203), START is the JUMP at tick 422, the round's time-up at match frame 3600 puts the
# result screen at tick 4382, and the selection screen is back at tick 4984.
#
# Every later round is a REMATCH round. The selection screen re-appears with the previous
# round's characters and settings still in FrontendState, so the stage page only has to be
# walked to START (row 0 -> 7; row 1 is skipped while stage == 0) and the round keeps the
# settings it had. Replaying the value taps instead would WRAP the carried-over values
# (measured: a rematch landed on 240 s/175 % where round 1 had 60 s/50 %). The random stage
# is re-rolled each round (FrontendState::stage stays 0), so the transcripts show a different
# stage per round.
#
# The stage page is configured by these taps alone: the synthetic pads stay neutral while it
# is open (their directions move that page's settings cursor, which made the round's settings
# depend on the tick the page happened to open on).
#
# Frames are front-end logic ticks, one per capture frame.
